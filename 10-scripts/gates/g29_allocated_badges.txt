# ───────────────────────────────────────────────────────────────────────────
# The Product Owner: *"We need unique screen ID - on every screen"*.
#
# Measured before anything was built: G29 reported **103 screens across 110
# routes, 68 carrying the r10 badge the visible tag renders — so 35 SCREENS
# SHOWED NOTHING AT ALL.** 23 of them had no id from either authority; 12 had an
# A1 `S`-id but no r10 badge, and the tag deliberately renders nothing for those
# because of the ruling below.

# A lane reported that there were only two roads and both broke something:
#
#   (a) RENDER THE A1 `S`-ID where there is no r10 badge. That reverses the PO's
#       own ruling of 2026-08-19, in that ruling's own words: *"Keep S series for
#       your reference for User and Product manager reference assign tags that
#       are visible on screen those should be as per modules how we are using in
#       r10"*. DECLINED.
#
#   (b) WIDEN G29 to accept an id no authority defines. That guts the one check
#       standing between us and the expensive failure: *"an invented id renders
#       on a screen, a PO photographs it, a defect is filed against it, and no
#       document anywhere can say what it is."* DECLINED.
#
# THE THIRD ROAD, TAKEN: the 2026-08-19 ruling says the tag follows *"modules how
# we are using in r10"* — **that is a SCHEME, not a closed list of the ids r10
# happened to draw.** r10 is a frozen prototype and cannot grow new badges, so
# the allocation authority has to be a file we own. This is that file.
#
# **G29 IS NOT WEAKENED. It still refuses an id no authority defines — it gains
# an authority, it does not lose a check.** An id must appear in A1, in r10's own
# `sid()`, or HERE. Nowhere else, and never nowhere at all.
#
# **No `S`-id is ever rendered**, so the 2026-08-19 ruling stands untouched.
#
# ───────────────────────────────────────────────────────────────────────────
# THE GRAMMAR — three capitals, a hyphen, a number; a dot for a sub-view
# ───────────────────────────────────────────────────────────────────────────
# r10's sixteen prefixes and the highest number it draws for each are the
# grammar, and new numbers continue it rather than restarting:
#
#     WRK 18 · SET 15 · PRM 8 · AST 8 · ACC 6 · PAY 5 · FIN 5 · RDS 4
#     BIL 4 · ONB 4 · PLN 3 · RAT 3 · CHG 2 · RPT 2 · DSH 1 · WFL 1
#
# A DOTTED SUB-ID NEEDS NO ROW HERE. `PLN-01.charges` is r10's own convention —
# the parent is the screen and the suffix is data — and G29 validates a dotted id
# against its PARENT. So `FIN-01.taxes` is lawful the moment `FIN-01` is (r10
# draws it), and `SET-16.retention` is lawful because `SET-16` is allocated
# below. Prefer a sub-id over a new number wherever a route is plainly a child of
# a badged screen: it consumes no number and it reads as what it is.
#
# ───────────────────────────────────────────────────────────────────────────
# TWO KINDS OF ROW, AND THE DIFFERENCE MATTERS
# ───────────────────────────────────────────────────────────────────────────
