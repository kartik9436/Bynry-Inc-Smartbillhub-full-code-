# claims, with the reason and what closes it.
#
#   <screen> <YYYY-MM-DD registered> <reason, and what closes it — min 40 chars>
#
# WHY THIS FILE EXISTS. Hard-won law 8 — "every screen needs a story" — has now
# been broken three times, and each time a screen reached a user unbuilt because
# it was nobody's to build and nobody's to notice:
#
#   DEF-006  S1, the public landing page, half-missing for a week.
#   DEF-129  S7, the tenant dashboard — THE FIRST SCREEN AFTER EVERY SIGN-IN —
#            rendering the literal string "SMARTBillHub — W0 scaffold".
#   DEF-137  S113, step 4 Review of the signup flow, found in review.
#
# THE COUNT IS EXACT, NEVER A CEILING (the G16/G20/G23 discipline). A screen that
# loses its claim must GAIN a line here, which is the moment somebody writes down
# why. A screen that gains a story must LOSE its line, so the register records the
# win and cannot keep claiming debt that is paid off. A line for a screen that IS
# claimed, or that A1 does not declare, is STALE and fails the gate.
#
# ⚠ ADDING A LINE IS NOT HOW A FINDING IS CLOSED. The fix is to author the story.
# A line buys time and writes down the price.
#
