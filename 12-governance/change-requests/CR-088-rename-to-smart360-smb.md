## 4 · WHAT IS ALREADY BUILT AND IS NOW WRONG

**Nothing is wrong. Three things are worth knowing before anyone starts:**

* **⚠ MY OWN WARNING ABOUT THE SAVED-DATA KEYS WAS OVERSTATED, AND THE CORRECTION MAKES
  THIS CHEAPER.** I reported that renaming `smartbillhub.portal.language` and
  `smartbillhub.signup.draft.v1` would *"silently reset every customer's saved language
  choice and drop any half-finished signup"*. **Both keys are `sessionStorage`, not
  `localStorage`** — `window.sessionStorage.getItem(GUEST_LANGUAGE_KEY)` and
  `safeSessionSet(SIGNUP_DRAFT_STORAGE_KEY)`, and both files say so in their own
  docstrings: *"tab-scoped, gone when the tab closes"*. A guest's language choice and a
  signup draft **already die when the tab closes**. The cost of renaming them is
  therefore *a person with a tab open at the moment of deploy*, and nothing else. The PO
  ruled beta makes it feasible; on this evidence it would be feasible outside beta too.

* **THREE SCREENS NEED NO EDIT AND WILL FOLLOW ON THEIR OWN.** `AppShell.tsx` renders
  `t("app.name")` twice — the sidebar brand lockup and `document.title` — and
  `SignInHelpPage.tsx` and `PricingPage.tsx` render it once each. They read the
  catalogue, so the value changes underneath them. **This is the argument for task B:**
  everything that already lives in a catalogue is free.

* **THE SIGN-UP SCREEN'S DOMAIN IS NOT HARDCODED AND IS NOT IN SCOPE.** `S110` shows a
  new utility the address it will live at — `smartbillhub.bynry.com/brazosbend` — and
  that host is `window.location.host`, composed by the same helper the router uses.
  **Renaming the platform does not rename the domain.** Whether `smartbillhub.bynry.com`
  becomes something else is a deployment and DNS decision, is nobody's code change, and
  is explicitly outside this CR.
