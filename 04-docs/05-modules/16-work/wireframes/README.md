# Wireframes — one image per screen, cropped from §13 *Screens to build*

**Source:** *SMARTBillHub Work Module Blueprint — §13 Screens to build*, exported by the Product Owner as its own
PDF on 2026-09-03 (`Screens_to_Build.pdf`, 30 pages, 2.3 MB; read at `2.128.2 · 47108051`). The parent
blueprint (16.3 MB) is over the 10 MB download cap and its pages cannot be rendered; **this file is the only
image source for the Work module so far.** Rendered at 110 dpi with PyMuPDF, each image cropped from the
screen's `WS-` heading to the *Proves…* caption beneath the frame, stitched where a drawing crossed a page
break, palette-quantised to 64 colours. **21 files, 0.70 MB.**

**These are the layout reference `08-screen-layouts.md` was written from, and the picture hard-won law 6 says
to diff the running app against.** A builder opens the image beside the story. Nothing here outranks B14 —
where a drawing and a B14 rule (or a PO ruling) disagree, B14 wins and `08-screen-layouts.md` says where.

**Twelve of the module's thirty-three screens are NOT in this file**, because §13 draws only the new builds:
`Work-001`–`006` and `Work-018`–`020` exist in the product today (blueprint §12 / §12.1 — the New connects
list, connection detail, the order drawer, the New Connect wizard step 6, the blank templates page, the Work
rail entry, the two Settings groups, the four disabled Assets controls) and `Work-010`–`012` are the
technician's phone (blueprint §14). **Their drawings live in the unread half of the parent document** and are
owed when it, or those sections, arrive under 10 MB. `Work-031` (taxes on a work order) IS drawn here but is
**not to be built for now** — PO ruling 2026-09-03, *"Dont add Tax on work order - for now"*.

The `Work-nnn` id equals the blueprint's `WS-nn` (PO ruling 2026-09-03, *"Use Work-nnn - code for this"*).
