**Boundary rule (B1):** no other module writes this module's tables; cross-module reads via service functions only. Payments posts NOTHING itself (ledger posting service 🔒) and never edits a bill; every email/SMS/print it produces is a queue-write to the platform outbound table (BR-NOT-005) — never an inline send.
**Cardinal date rule (BR-PAY-021):** posting date ≠ clearing date, always both. ~~Billing consumes POSTING (posted by due date = on-time even if cleared later)~~ ⚠ **AMENDED PO 2026-08-11 (OQ-131 → BR-BIL-071): for the LATE-FEE test billing consumes the ACTUAL date the money arrived — the CLEARING date.** Both dates are still always recorded; NSF/failure and bank rec hang off CLEARING. **A TYPED posting date is midnight in the utility's own timezone (PO 2026-08-12, OQ-153) — blocked today by DEF-082, the missing company-settings timezone dropdown.**
