Billing consumes everything upstream and feeds everything downstream. It never measures, never prices, never posts, never pays — it **orchestrates** (pre-session model §1): assemble inputs per account (accounts/status class + plan snapshot · rate schedules per tariff version · assets/multipliers · committed reads per channel · money context) → run the pipeline **select → check → exceptions → totals → confirm → send** (six steps, run in the **five phases** the PO ruled on 2026-08-11 — prepare · calculate-in-background · breaks · summary+gate · release; BR-BIL-050, mapping in EP-BIL-01 §Phase map) → produce **one customer document + N GL-coded invoice lines + one balanced journal entry per bill** (BR-BIL-011) → queue delivery. Rating math is the rating module's engine (🔒 human-owned, GT-tested); ledger writes belong to the posting service alone.

**Owns (B2 + Addendum r10):** `bill_runs` (+status lifecycle, `parent_run_id`+scope), `bill_run_exclusions` · `invoices` (+`bill_type`, template pin) · `invoice_lines` (+`gl_account_id` stamp, `taxable`) · `adjustments` · `credit_notes` · correction workflow tables (`correction_cases` + bulk results) · outbound delivery queue · finance account mapping (`service_gl_map`, `tax_authority_gl_map`, designations) · `bill_templates` + `bill_template_versions` · `account_budget_status` **+ `account_budget_events`** (the append-only trail US-BIL-019 TC-6 makes the variance balance derive from — an Eng-Lead DDL call under r10 #15, recorded in the decision log; **BUILT 2026-08-11**, migrations 0012/0013) + budget settings (which live in TENANCY as the S69 rule page, not here) · balance-transfer transaction + write-off support · reason-code lookups.

**Hard invariants (CLAUDE.md/B8):** issued invoices/lines immutable — corrections are credit notes + rebills (BR-BIL-004) · runs idempotent per (tenant, cycle, period), catch-up sub-runs scope-keyed (BR-BIL-005/015) · GL stamped per line at issue, history never re-maps (BR-BIL-010) · only the posting service writes journal lines (BR-BIL-011) · free-typed amounts never exist on any bill (BR-BIL-019/020) · every money action writes `audit_log` · all mechanics tenant-configured with seeded defaults, nothing hardcoded (BR-BIL-021).

**Boundaries — what billing does NOT own (model §15):** dunning/disconnect notice workflow = collections (J4; billing only computes the late fee) · statements over a range = reports (statement ≠ bill, A19) · refund execution, payment plans, autopay capture, payment allocation execution = payments · rendering engines + send infrastructure = notifications (billing owns queue records + pinning) · rating math = rating engine 🔒 · ledger writes = posting service 🔒.
