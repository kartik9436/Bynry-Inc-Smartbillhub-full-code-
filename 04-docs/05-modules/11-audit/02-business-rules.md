| BR-AUD-019 | **An actor that is NOT a person is NAMED, and VERSIONED where it has a version — and it carries no user id.** Three nullable columns on `audit_log`: `actor_kind` (`runbook` \| `job` \| `import` \| `integration` — a code-defined closed set, the same seeded-only posture BR-AUD-005 takes for event codes), `actor_label` (what a clerk reads: *Returned payments*) and `actor_version` (text, optional: *4*). **The three readings stay distinct without a backfill:** `actor_kind` set = a named non-person actor · `actor_user_id` set = a person · both null = an unnamed system job, which is BR-AUD-003 unchanged. **A named actor NEVER also carries a user id** — refused at the writer (`core.audit.write_row`) and by the table's own CHECK (`ck_audit_actor_named_never_borrows_a_login`). **The name and the version are two fields and are never stored as one sentence:** a stored *"Returned payments, version 4"* is English in a database column that eleven catalogues cannot translate (B14 rule 35), so the screen composes it in the reader's language. No id is ever drawn (B14 rule 31) | `BR-RBS-015` (PO-ruled: *the runbook is the audit actor, named and versioned; it never borrows a user identity*) · spec B1 (*"an automated action currently has no name"*) · CLAUDE.md hard rule 7 · BR-AUD-002 (append-only ⇒ nullable, no backfill) · `CR-075` task `L1` · decision log 2026-09-06 | CONFIRMED — the behaviour was already ruled by `BR-RBS-015`; US-AUD-010 is the platform capability that lets it be expressed, not a new decision | US-AUD-010/TC-1..10 · TC-RBS-12 |
