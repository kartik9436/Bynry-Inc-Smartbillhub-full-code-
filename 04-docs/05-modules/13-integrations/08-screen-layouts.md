# 13 · Integrations — screen layouts (the substrate, `CR-069`)

**One entry per screen, written while looking at the frames of *The Integrations Surface* — the wireframe
pack the Product Owner exported on 2026-09-03: 41 frames across 24 figures, read at `2.120.1`, status *design
— not built*.** Each frame is real markup rendered by one stylesheet, and the pack says its class vocabulary
is deliberately small — *"one `.win` per frame, then `.scr-hd`, `.pill`, `.counts`, `.tbl`, `.note`, `.frow`
and `.acts`. Nine providers do not become nine components."* — which is exactly B14 rule 21's shape and is
why `09-component-inventory.md` is short. Images are `wireframes/frame-NN-N.png`; each entry names the
**frame**, the **regions top-to-bottom**, the **components** from the inventory, and the commitment cards
(`C##`) the pack draws on it.

**Where a frame and B14 — or a PO ruling, or an open question — disagree, the rule wins and the entry says
so.** The pack's own closing page asserts rules 31, 32 and 21 hold on all 41 frames (*"no database id is
ever the visible value of a field … every card description above is one sentence; none says `BR-INT-003`,
and the word idempotency appears on no frame"*); the places this file adds are in the closing table.

**The pack's chrome is not the product's.** Every frame carries a mono header bar (*25.1 CONNECT, CUSTOM
SMTP · MODAL*) and a right-hand badge (*PROPOSED · PHASE 1*, *DESTRUCTIVE*, *SHAPE ONLY*); frame 25.1 also
carries a segmented *CATEGORY — A CONTROL FOR THIS DRAWING ONLY*. None of that is built.

**Screen ids.** The pack numbers its screens `S8 · S116–S121` as the design did; **this repository allocated
`S141`–`S146`** (`CR-069` §9), so `S117` in a frame header is `S142` here, `S118` is `S143`, `S119` is `S144`.
