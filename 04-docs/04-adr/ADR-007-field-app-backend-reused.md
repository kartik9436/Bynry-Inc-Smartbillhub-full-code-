# ADR-007 — The Work backend is untouched and fully reused by the field app

- **Status:** **Accepted** (design decision; consistent with decision log 2026-10-21 conflict 6, *"`06-backend/apps/work` is reused"*).
- **Date:** 2026-10-21
- **Deciders:** Product Owner (rulings named below) · design author (the design conversation of 2026-10-20/21) · recorded by lane DOC-C under `CR-187-BRC10`
- **Source:** *SMART360 Next Field App* design canvas, page *Architecture decisions* (version of 2026-10-21, app version 2.587.0), decision **AD-02**. Change request `CR-187-BRC10`.

## Context
The server half of field work — sync, safety, push, audit — was built and proved for the web field app under `CR-070`.

## Decision
`06-backend/apps/work/` stands as it is: the per-item sync contract (accepted / duplicate / refused), the PostgreSQL SAVEPOINT per item (hard-won law 14), server-side safety re-derivation, the push job on its own queue, and the audit trail. The API contract does not move.

## What it reverses
Nothing.

## Why
This is the expensive, law-grade half, and React Native consumes it unchanged.

## Evidence
The design's *Mobile data* page §12, checked against the code on 2026-10-21: `work_order_attachments` (idempotency key minted on the handset, scoped to tenant + work order + key), `work_photo_links` (the photograph declaration), `TechnicianDevice`, and versioned `work_order_templates` already exist.

## Cost
New pieces are additions, not changes, each in its own small PR with `openapi/schema.json` regenerated by its tool, never hand-merged (law 5): a `source` on documents, field-capture columns on `meter_reads` (position, accuracy, device clock, can't-read reason, off-route flag), a can't-read reasons catalogue, a photograph COUNT per task (today a boolean), freshness on a template step, a reconnect-fee seam method, the capture credential (ADR-026), and a template catalogue read for the handset.
