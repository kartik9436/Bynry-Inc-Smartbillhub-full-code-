# src/api — the typed client (FI-01) + query setup (FI-02)

**`06-backend/openapi/schema.json` is the generated artifact**; everything here is **hand-written against it**.

That file lives on the backend side and nowhere else. A copy used to sit in this
directory too, and by 2026-08-10 the two had drifted — the local one still
described the pre-path-tenancy API (80 routes, not one `{tenant}` segment) while
the backend served 83 with 77 tenant-scoped. One generated file committed twice
drifts; committed once cannot. The remaining copy is regenerated by
`cd 06-backend && python manage.py export_openapi`, and both CI and
`tests/test_be11_openapi.py::test_be11_tc05` fail if it is stale.

## What is generated vs. hand-written

| File | Origin |
|---|---|
| `client.ts` | Hand-written. The ONE HTTP path out of the app. |
| `endpoints.ts` | Hand-written. Thin typed wrappers for the endpoints the shipped screens use. |
| `queryClient.ts` | Hand-written. FI-02 TanStack Query defaults + entity keys. |

**Why hand-written, and for how long.** The B8/FI-01 rule is "generated client only". Two facts make a codegen step impossible today and a hand-written layer honest:

1. **No codegen dependency may be installed** (offline build environment) — there is no `openapi-typescript` / `orval` in `package.json`.
2. **The export carries no body shapes.** The backend's views are plain DRF `APIView`s without serializer classes, so drf-spectacular emits paths, methods and parameters but renders every response as `"No response body"` — the snapshot's `components.schemas` is literally empty. Generating from it today would produce 83 routes typed as `unknown`.

So the request/response types in `endpoints.ts` are written from the schema's paths **plus** the payload builders behind those routes (`06-backend/apps/*/api.py`, `selectors.py`, `services.py`), each field commented with the rule it carries. When the backend gains serializer classes and a codegen step is added, this directory's types become generated and this README changes with it. Until then: **no hand-written `fetch` outside `client.ts`** — that half of the rule is absolute.

Only the endpoints the shipped screens consume are typed. The rest of the 83 routes arrive with the packets of the screens that use them.

## The contract `client.ts` implements

Ratified in `04-docs/02-decisions/12-engineering-plan.md` §3 + Addendum r1 §3-expanded and `04-docs/01-spec/11b-api-audit.md` §3:

- **Error envelope** (G1) `{code, message_key, params, field_errors[], br_ref, trace_id}` → the typed `ApiError`. `formErrorEnvelope()` adapts it to what a `FormModal` (US-SHL-009) renders. UI text always comes from `message_key` through the i18n catalog — the server sends codes, never prose (TD-16/G14).
- **Full HTTP series** (G2): 200/201/204 data · **304 + ETag** pass-through on GETs (`ifNoneMatch` in, `notModified` + `etag` out) · 4xx/5xx as `ApiError` · **429 + Retry-After** honored by the backoff.
- **202 + job polling** (G3): `acceptedJobId()` reads the 202 body, `client.pollJob(id)` polls `GET /api/jobs/{id}` to a terminal status with `onProgress` for wizard progress rows.
- **Retry with backoff on 429/502/503/504 — idempotent GETs only.** A mutation is never replayed: idempotency is the server's guarantee (CLAUDE.md #6), and a client-side replay of a bill run or a provisioning commit is a second write.
- **`credentials: "include"`** so the httpOnly session cookie rides along (BR-IDN-006).
- **The tenant travels in the URL, never in a body or header** (BR-TEN-003 / G4, as amended by the PO's 2026-08-10 path-tenancy ruling). `client.ts` §API URL shape is the ONE place that builds it:

  | Contract path passed by `endpoints.ts` | URL on the wire |
  |---|---|
  | `/settings/company`, `/plans`, `/tenants/checklist`, … | `/api/{tenant}/…` |
  | `/public/…`, `/tenants` (POST, provisioning), `/jobs/…`, `/exports…` | `/api/…` — no tenant |

  The tenant is read from the browser's own path (`/{tenant}/…`, via `src/routing/tenantPath.ts`) per request, so it follows client-side navigation; the base URL stays **same-origin** so the session cookie is sent. A tenant-scoped call made with no tenant in scope **throws** — it is never quietly sent to an un-tenanted URL.

## Known gaps (reported, not resolved here)

- `client.ts` reads no env var: a dev proxy for a split-origin dev setup belongs in `vite.config.ts`, not in a base URL that would strip the session cookie. In containers there is no split origin at all — the frontend serves the SPA and passes `/api/*` through to the backend, so one origin is the deployed shape too.

*(Two gaps listed here through 2026-08-10 are CLOSED and removed: `GET /api/jobs/{job_id}` is registered and appears in the snapshot, and the `/api/{tenant}/…` mount has landed — 77 of 83 published routes carry the segment. The mocked-client tests are no longer the only source of truth for either.)*
