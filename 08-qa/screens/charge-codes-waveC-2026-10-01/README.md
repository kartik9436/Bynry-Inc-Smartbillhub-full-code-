(8 tests, all passing). Each `<NN>-<state>.built.png` sits beside `<NN>-<state>.ref.png`, a copy of the
reference image it is compared with.

**How to read the verdict.** *Matches* means the screen shows the same things in the same arrangement — the
same panels, tiles, tabs, columns and fields in the same order. It does NOT mean the same pixels:

* every figure in a drawing is an illustration (B14 rule 37) — the built shots carry the walk's own data
  (codes like `BT6011`, $0.00 tiles on a fresh code, *Not set* GL accounts);
* our UI standard decides spacing, sizes, type and components on every screen (B14 rule 44), so the kit's
  table headers, field widths and panel fills differ from the mock-up's by design;
* the built shots include the product frame (sidebar, top bar, version); the drawings are cropped to the
  content.

**Result: 76 match, 7 differ.** Fixed in wave C because they broke the drawings' arrangement:
the tiles and scheduled band moved ABOVE the tab strip on all 37 View states (06–42); *How it bills* reads two
rows of three; the Plans tab draws Plan · Customer class · Accounts; rows priced by class read Residential
first; a base on a service billed as a share says *Usage % is on the rate schedule.*; the base Minimum column
(images 11, 51). The two pricings wave B showed disabled (DEF-RAT-8753) are offered and saved (46, 48, 61, 64,
67, 70, 76–78, 31, 41).

**What still differs, and why it is left:** 05 (the kit's empty state — rule 44), 26–29 (the deposit *Held*
tile has no read — `DEF-RAT-8821`, open), 40 (a code priced *entered when used* stores no dated price, so it has
no Effective from), 51 (the drawn *Minimum is set on the rate schedule.* is rationale — B14 rule 33 puts it at
zero words on screen).
